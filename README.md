## Overview

StationSafe predicts, one hour in advance, whether a Dublin Bikes station will run out of bicycles. It is built on an XGBoost classifier trained on 7 million hourly station-hours spanning January 2019 to May 2026, combining JCDecaux availability data with Met Éireann weather observations and the Irish public holiday calendar.

On a held-out 2026 test set the model achieves an AUC-ROC of 0.9750 and catches 94.6% of actual stock-out events. Every prediction is accompanied by a SHAP feature-attribution explanation, delivered through a Streamlit dashboard with live and historical modes.

| Metric | Value |
|---|---|
| AUC-ROC | 0.9750 |
| Recall | 94.6% |
| Precision | 60.3% |
| F1 | 0.7368 |
| Brier score | 0.0680 |
| Stock-outs caught | 50,275 of 53,135 |

## Requirements

Python 3.12 or later, 16 GB RAM, ~2 GB disk.

```bash
pip install -r requirements.txt
```

Versions are pinned. Do not upgrade XGBoost after training — SHAP values are sensitive to version differences, and a mismatch will produce incorrect waterfall attributions.

## Data setup

Three sources must be downloaded before running anything.

**Dublin Bikes historical availability** → `Datasets/Dublin Bikes dataset/`
https://data.smartdublin.ie/dataset/dublinbikes-api-archive

Place all `.csv` files directly in the folder, no subfolders. Roughly 66 files. The cleaning script auto-detects three format generations by inspecting column names (Format A: 2019–2021, B: 2021–2024, C: 2024 onwards). `2021_10.csv`, `2021_11.csv` and `2021_12.csv` are excluded automatically — they duplicate data already present in a quarterly file.

**Met Éireann hourly weather** → `Datasets/Met Eireann weather data/`
https://www.met.ie/climate/available-data/historical-data

Phoenix Park station (code 175). Save as `phoenix_park_hourly_raw.csv`. The file has 15 metadata header lines; the cleaning script handles this.

**Irish public holidays** → `Datasets/Irish calendar/`
https://data.gov.ie/dataset/irish-public-holidays

One CSV per year, named `2019.csv` through `2025.csv`. Each needs a `date` column and a `type` column where holidays are labelled `Public holiday`.

## Running the pipeline

Run everything from the project root. Paths are relative to it.

```bash
python Cleaned-datasets/01_clean_weather.py     # < 1 min
python Cleaned-datasets/02_clean_calendar.py    # < 1 min
python Cleaned-datasets/03_clean_bikes.py       # 5–10 min
python merged-datasets/04_aggregate_and_merge.py  # 10–18 min
```

The last script aggregates 51 million raw 5-minute readings to 7 million hourly rows, merges all three sources, and imputes two 2024 data gaps using same-period-last-year patterns.

Then run the notebooks in order:

| Order | Notebook | Produces |
|---|---|---|
| 1 | `merged-datasets/03_feature_engineering.ipynb` | `features_dataset.parquet` |
| 2 | `Models/04_model_training.ipynb` | `xgboost.pkl`, `random_forest.pkl`, `logistic_regression.pkl` |
| 3 | `Models/05_shap_analysis.ipynb` | SHAP plots |

## Dashboard

```bash
streamlit run app.py
```

Opens at `http://localhost:8501`.

**Live Mode** fetches real-time availability from the JCDecaux API for all 114 active stations plus current weather from Open-Meteo, then scores the whole network in a single batched call. Requires an API key:

```bash
# Windows PowerShell
$env:JCDECAUX_KEY="your_key_here"

# macOS / Linux
export JCDECAUX_KEY="your_key_here"
```

Free keys from https://developer.jcdecaux.com.

Lag features for timestamps beyond the dataset boundary fall back to per-station hour-of-day medians. This is expected behaviour, not an error.

**Historical Mode** browses any station, date and hour from 2024 onwards, showing predicted probability, a SHAP waterfall, a 24-hour risk trend and the network-wide map for that timestamp. Works entirely offline, no API key needed.

## Design decisions

**XGBoost over a neural network.** XGBoost is compatible with SHAP's TreeExplainer, which computes exact Shapley values in polynomial time. Neural networks require approximate SHAP values — slower and less precise. Per-prediction explanation is central to the system's purpose, so exactness matters more than marginal accuracy.

**MultiIndex lookup instead of `shift()` for lag features.** `shift(n)` assumes adjacent rows are exactly n periods apart. This dataset has internal hourly gaps wherever sensor data was missing, and a shift on a gapped series silently returns the wrong value with no error. MultiIndex lookup computes the target timestamp explicitly and returns NaN if it doesn't exist, which is then handled by the median fallback.

**Open-Meteo rather than Met Éireann for live weather.** Met Éireann's API returns HTTP 403 when called programmatically. Open-Meteo is free, needs no key, and permits automated access. Wet-bulb temperature and vapour pressure are derived from its outputs using the Stull approximation and Magnus formula respectively, matching the variables used in training.

**`scale_pos_weight` rather than SMOTE.** The dataset has roughly a 1:6 ratio of stock-out to non-stock-out hours. Synthetic oversampling caused an `ArrowMemoryError` at 5.6 million training rows on a 16 GB machine. `scale_pos_weight` upweights positive examples during gradient computation without generating synthetic data.

## Troubleshooting

**`FileNotFoundError`** — you are running a script from inside its own folder. Run from the project root with the full relative path.

**`ArrowMemoryError` in the dashboard** — not enough RAM. The dashboard loads 2024 onwards by default; narrow the date filter in `load_data()` further.

**SHAP waterfall blank or showing wrong values** — the installed XGBoost version doesn't match the one that produced `xgboost.pkl`. Reinstall from `requirements.txt` and retrain.

**`KeyError` loading the features dataset** — regenerated by an older version of the feature engineering notebook. Delete `features_dataset.parquet` and re-run notebook 1.
